# Agent Studio · 统一 Agent 基建平台

用于需求评审的纯前端 MVP Demo，覆盖社区穿搭、生态守护和电商售后三类 Agent 的共同生命周期。

**在线体验：<https://Shawyishere.github.io/agent-platform-mvp/>**

全部数据、模型回答、评测、流量、角色与监控为合成演示。无真实模型 API、业务数据、生产流量或后端；状态仅保存在当前浏览器的 localStorage。请勿输入真实用户数据或密钥。

## 建议评审顺序

1. 从工作台选择 A 团队或创建模板，修改配置并保存，在调试区查看输入与示例输出。
2. 选择缺陷候选运行评测，检查发布被拦截；改回标准候选，重新评测。
3. 通过评测后启动灰度，查看样本、效果和护栏；收集模拟样本后放量，或注入异常后回退。
4. 进入 B 团队，检查独立审核角色与影子验证要求，体验批任务失败重试；旧政策失效时必须人工兜底。
5. 进入 C 团队，更新知识版本并保存，检查旧评测失效；体验多轮答疑、依据引用与转人工。
6. 查看 Trace、反馈回流和操作审计；刷新后状态保留，左下角可重置演示。

## 产品取舍

一期保留模板搭建、模型与知识配置、评测门禁、版本发布、实验观测、回退及治理底线。差异以模板、运行模式和发布策略表达。复杂画布、多 Agent 协作、开放插件市场及自动优化留待二期。

灰度用于控制风险暴露，不能代替有统计设计的 A/B 实验。示例面板没有证明业务提升，也不能证明百万级调用能力。B 输出辅助判定，不自动处罚；C 不执行退款。

## 本地运行

无需安装依赖或构建。直接打开 `index.html`，或使用任意静态 HTTP 服务托管本目录。使用 HTTP 服务时，状态按该域名保留。

文件：`index.html` 为页面入口，`styles.css` 为样式，`app.js` 为数据、状态与交互逻辑。GitHub Pages 从 `main` 分支根目录发布。

## 实现边界

前端演示真实控制可点击流程和状态转换，包括配置变更使评测失效、失败门禁、角色步骤、模拟灰度/影子及回退。浏览器角色切换不是鉴权，localStorage 不是可靠审计存储。真实生产仍需服务端权限、数据隔离、持久化、幂等队列、模型网关、压测、监控和业务方签收。
