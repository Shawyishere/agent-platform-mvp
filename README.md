# Agent Studio · 统一 Agent 基建平台

用于需求评审的纯前端 MVP Demo，覆盖社区穿搭、生态守护和电商售后三类 Agent 的共同生命周期。

**在线体验：<https://Shawyishere.github.io/agent-platform-mvp/>**

## 建议评审顺序

首页点击 **开始评审**，按 A → B → C 体验同一骨架下的三种发布策略。

1. **A · 缺陷被拦 → 标准通过 → 灰度 → 放量 → 注入异常 → 回滚。** 在效果评测中选择缺陷候选并运行，检查发布门禁阻断；切回标准候选重新评测。通过后发布 10% 灰度，推进两次样本，完成人工效果评审并确认全量发布。最后到观测页注入质量 / 性能异常，回滚完整版本包，核对恢复后的版本、模型与知识。
2. **B · 独立审核 → 影子验证 → 政策失效后人工兜底。** 通过评测后，切换右上角的独立审核人，确认当前候选包，再启动影子验证。推进两次样本后切换生产辅助链路；在观测页启用旧版本政策失效，检查旧包回退被禁用，转为人工兜底。
3. **C · 知识更新使评测失效 → 索引失败阻断发布。** 先运行一次通过的评测，再到构建页更新知识，检查旧评测失效。返回评测页启用知识索引失败并运行评测，检查发布被阻断；恢复索引、重新评测后发布 10% 灰度，推进两次样本即可达到放量门槛。
4. 按需查看沙箱调试、多轮答疑、批任务重试、Trace、反馈回流和操作审计。刷新后进度保留，右上角可重置。

三个策略均用两次推进完成样本积累：

| Agent | 每次推进 | 最低样本量 |
| --- | ---: | ---: |
| A · 社区穿搭灵感 | 2,500 | 5,000 |
| B · 生态守护 | 1,500 | 3,000 |
| C · 电商售后答疑 | 500 | 1,000 |

## 产品取舍

一期保留模板搭建、模型与知识配置、评测门禁、版本发布、实验观测、回退及治理底线。差异以模板、运行模式和发布策略表达。复杂画布、多 Agent 协作、开放插件市场及自动优化留待二期。

## 本地运行

无需安装依赖或构建。直接打开 `index.html`，或使用任意静态 HTTP 服务托管本目录。使用 HTTP 服务时，状态按该域名保留。

文件：`index.html` 为页面入口，`styles.css` 为样式，`app.js` 为数据、状态与交互逻辑。GitHub Pages 从 `main` 分支根目录发布。

## 实现边界

本作品为纯前端原型：数据、模型回答、评测和流量使用预置样例，配置失效、发布门禁、角色步骤及回退由前端状态逻辑控制，进度保存在当前浏览器的 localStorage。生产接入需补齐服务端鉴权与隔离、持久化审计、模型网关、任务队列和容量验证；请勿输入真实用户数据或密钥。

本 Demo 按提交者确认采用 GitHub 交付，未通过 REDcowork 构建。

## 视觉设计

界面采用浅蓝与白色的云平台风格，首页优先展示评审导览、主链路与各 Agent 的发布策略。`assets/studio-hero.png` 和 `assets/scenario-icons.png` 为使用内置 image_gen 生成的原创 3D 插画，当前首页保留卡片插画；完整提示词见 [`assets/generation-manifest.json`](assets/generation-manifest.json)。
